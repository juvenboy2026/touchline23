# Notes for agents

- This repository runs one Nintendo Switch game natively on Apple platforms: FIFA 23 Legacy Edition (title ID `01001C8016B4E000`, base 1.0.0 `v0`, update 1.0.3 `v196608`), the game's own code running, rewritten only where Apple's kernel requires it. There is exactly one game profile, `dm/games/01001C8016B4E000/`: `game.tsv` (program ID, modules `main sdk`, `mem_reserve 0x140000000`, `archive_format easf`, container `datax.big`, `tex_dyn_slots on`, the two build rows) plus its shader tables (a `patches.py` only when one of its builds needs a rewriter cut; this game needs none, and `dm/tools/sdk_patches.py` is empty for the same reason). Tools pick it with `DM_GAME`; the build scripts pass it themselves. There is no default game: the tools stop and list the profile otherwise. Put per-game values in the profile, not in code ([dm/games/README.md](dm/games/README.md)).
- Public upstream is [nxnative](https://github.com/seedds/nxnative); the independently maintained product is [Touchline 23](https://github.com/ohxiaoguang/touchline23). Engine execution, services, NVN → Metal and translation infrastructure retain upstream authorship. FIFA compatibility/resource/audio work and packaging also include the maintainer's earlier adaptations; do not attribute all of those to official upstream or claim the entire engine as original work. Keep private development repositories out of public entry points. See [docs/UPSTREAM.md](docs/UPSTREAM.md) and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Do not add other game profiles automatically.
- Prefer general optimizations and fixes to game-specific rules. Performance work (frame pacing, power, caches, load times) counts here as much as correctness. First look for a change that holds for any game: Horizon / NVN semantics, or what the binary, its SDK version, its imports or its files show. Use a game-specific rule (a profile key, a rewriter cut, a build-ID gate, a per-game branch in the host) only when no general rule can do it.
- Per-build knowledge is keyed by the NSO build ID: rewriter cuts, observation gates and frame-step stubs in the profile's `patches.py` (the game's own modules) or `dm/tools/sdk_patches.py` (Nintendo's `sdk` module), which `dm/tools/patch_nso.py` loads. The profile's `build` rows are the builds the game was brought up on; host behaviour that uses fixed module addresses checks `module_t.build_id`. When a new game build appears, carry addresses over with `dm/tools/nso_fnmap.py` and check them by disassembly; never let fixed addresses run on a build they were not found in.
- The game's shaders are EA's EASF archives (`data3.big` and the BIG4 siblings): `scripts/build_fifa23.py --shaders-only` decodes them into a package (discovering the EASF key in the game's own `main` when no key file is given) and `dm/gfx/tools/dmsh_build.py` translates and compiles them. The base game's 386 programs give 520 libraries for macOS and 520 for iOS; the update adds no shader. What those shaders needed is in [docs/fifa23/shader-fixes.md](docs/fifa23/shader-fixes.md) and [docs/fifa23/shadow-investigation.md](docs/fifa23/shadow-investigation.md).
- Scripts the user runs live in `scripts/` at the repository root: `build-mac.sh`, `build-ios.sh` (both over `touchline_build.py`), `build_fifa23.py`, `build_packaging_gui.py`, `build_ipa_from_nsp.py`. Each runs from a terminal (non-zero exit on error) and prints `[RED] ` on failure. Tools that only agents or other scripts call stay under `dm/`.
- A build reuses what an earlier run made: `--exefs`, `--patched`, `--shaders`, `--ios-shaders`, `--shader-pack`. Never regenerate the 520 libraries to test an unrelated change; the tool refuses a library whose `inputs.tsv` does not name this profile's inputs, and that refusal is the check, not an obstacle. Work goes to `build/` (ignored by Git); artifacts go to `Release/`.
- Game files, keys and anything extracted from them live in the game's NSP folder, never in this repository and never in the home folder (it is nearly full): the work folder for extraction, runs and analysis belongs on that drive. Do not print key values. Game dumps, extracted RomFS, keys, saves, logs, dumps, metallibs and built Shader sources are never committed.
- Language: maintain `README.md` with `README.zh-CN.md` and `docs/packaging-gui.md` with `docs/packaging-gui.zh-CN.md` in parallel. Launcher/packaging UI strings use the existing English/Simplified Chinese catalog and tests. Other technical docs, source comments, diagnostics and script output remain in English; original third-party texts are preserved verbatim. Red log lines (something unimplemented or wrong) start with `[RED] `. Text that must match a game's own Chinese data is written as escapes (`"\xE8\xB5\xB7"`), never as characters.
- The shader translation chain has one version, `DMSH_CHAIN` in `dm/gfx/nvn/dmsh_chain.h`, which the host is compiled with and loads only libraries of. It covers `dm/gfx/tools/dmsh_*`, `Program.cs`, `ios_metal.py` and `dmsh_chain.lock`. A profile's own inputs (`shader_map.tsv`, `shader_facts.tsv`, `shader_pairs.tsv`, `bf_want.tsv`, its `shader_*` / `nvn_*` keys) are not part of it: they are in each shader's cache key, and their digest stamps the libraries (`b-<V>/inputs.tsv`). The procedure:
  1. After changing a chain tool, run `dmsh_chain.py --header` once and commit `dm/gfx/nvn/dmsh_chain.h` with the change (`dm/tools/tests/test_nsp_chain.py` fails on a stale one).
  2. After that, or after changing a profile's inputs, rebuild the Shaders: a full `dmsh_build.py` run (macOS and, with `IOSOUT`, iOS) stamps its libraries and writes the profile's `c1_full.tsv` and `cb_extent.tsv` from its macOS outputs (Git ignores them; the host takes them only beside the stamp they name).
  3. Rebuild the host.

  The translator is `dm/gfx/tools/dmsh_xlate_bin`, which matches `dmsh_chain.lock`; a fresh `dotnet publish` does not.
- iOS builds are unsigned IPAs that the user sideloads and tests; diagnostics come back as the app's `Documents/log.txt`. Do not sign or install builds on the user's devices. The bundle identifiers are the profile's `bundle_id` row (`com.ohxiaoguang.touchline23`) and `com.ohxiaoguang.touchline23.packaging` for the packaging App; neither may collide with another port's.
- Run tests locally; this project does not use GitHub Actions. Keep test sources, local build/test scripts and publication checks when removing obsolete UI. Preserve exact binary, source and original-license provenance; never change a historical SHA to make a public link work.
- Commit only when asked. In this repository, use the repository-local Git identity for `ohxiaoguang` with `user.useConfigOnly=true`; do not override it with the upstream author's identity or modify global configuration. Preserve upstream authorship and third-party contribution notices.
